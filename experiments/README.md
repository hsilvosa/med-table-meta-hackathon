# Experiments (spikes)

Throw-away scripts that de-risked the design. Run from the repository root. They read `data/` (CIMA photos, cut-outs, scenes) and write to `experiments/out/` (ignored by git). SAM scripts need `.venv-sam3`; the rest run with `.venv-app`. The VLM scripts need a local llama-server on port 8082 (command in `vlm_client.py`).

| Script | What it tests |
|---|---|
| `sam3_image_smoke.py` | SAM 3 image model with text prompts on synthetic scenes |
| `sam31_video_smoke.py` | SAM 3.1 multiplex checkpoint on a still image, with the Windows / consumer-GPU workarounds |
| `sam3_box_crops.py` | SAM 3 "box" crops of the scenes, matched to ground truth (IoU >= 0.5) |
| `vlm_read_packs.py` | Qwen3.5-9B reading CIMA pack photos; CN checked against check digit and CIMA |
| `vlm_eval.py` | Qwen3.5-9B on the SAM crops and on a fictional medication sheet |
| `decode_robustness.py` | How small and blurred a rendered pack Data Matrix can be and still decode (zxing-cpp, whole image vs tiled) |
| `meta_smoke.py` | Meta Model API client (`muse-spark-1.3`): connectivity, one pack photo, the fictional sheet, cost per call |
| `sheet_reader_eval.py` | `sheet_reader.read_sheet` (Meta or local backend) scored against the fictional sheet's truth |
| `candidates_eval.py` | For SAM crops without a code: does the model's reading plus CIMA search put the true medicine among the candidates? |
| `demo_plan.py` | Builds a demo plan from invented medicines: PDF, `.ics`, voice WAVs, PNG preview |
| `make_fictional_sheet.py` | Renders the fictional medication sheet with phone-photo degradations |

## Results (2026-10-26; small samples, read them as indications, not metrics)

- **SAM 3 / 3.1 run on an RTX 3060 under Windows** (5.4 GB / 6.4 GB peak, 1-2 s per prompt). They need bf16 autocast; SAM 3.1 also needs `use_fa3=False` and a wrapper around an upstream `init_state` argument bug (see the script). On 12 synthetic scenes SAM 3 matched 71 of 72 ground-truth packs (IoU >= 0.5) and made 10 extra detections.
- **Cut-outs (`scripts/make_cutouts.py`)**: on 50 random medicines, 50 pack cut-outs and 51 dosage-form cut-outs passed the checks; by eye the packs are whole and the pills clean. 3 of 31 oral-solid medicines got no pill.
- **Qwen3.5-9B on full CIMA pack photos**: brand or ingredient matched in 7 of 8; 6 CN reads, 5 accepted (check digit valid and present in CIMA for that medicine), 1 rejected by the check digit.
- **Qwen3.5-9B on small crops from synthetic scenes (73 crops, about 300 px, rotated, partly occluded)**: by the crude name check 28 correct, 2 abstentions, 43 wrong; 15 CN reads, 8 with a valid check digit, 6 of those present in CIMA for the true medicine. Wrong answers include invented ingredients and look-alike confusions. The check is crude (it also counts as wrong correct ingredients given without the brand, e.g. Xelevia read as MSD/sitagliptin), but the conclusion holds: the model must not identify packs. Identification comes from the pack code; the model only proposes candidates that the user confirms, and a CN is accepted only if the check digit, CIMA membership and the other fields agree.
- **Qwen3.5-9B on the fictional medication sheet**: 7/7 rows, 28/28 schedule cells and all remarks exact, 15 s. One clean synthetic sheet; real sheets are untested, so every line still needs caregiver confirmation.
- **Data Matrix robustness (`decode_robustness.py`, perfect rendered GS1 codes, 4 trials per cell, so only a rough guide)**: decoding works from about 3 pixels per module with blur up to 1 px, and needs about 5 pixels per module with blur of 2 px; at 2 pixels per module it fails once there is any blur. The tiled search adds little over decoding the whole image (e.g. 4 px/module with blur 2: 0/4 vs 2/4) and costs about 0.4 s instead of 0.04 s. A pack code is about 1 cm for 22-26 modules, so a 12 MP photo (4000 px) of a table 60 cm wide gives only about 2.7 pixels per module: borderline. A field of view of about 30 cm (about 5 pixels per module) is comfortable, so the design keeps the "show me the code side, closer" step. Real printed codes (glare, curved cardboard, print defects) will do worse; this has not been measured on real packs yet.

- **Meta Model API (`muse-spark-1.3`, standard tier)**: the token works from Spain. Three calls cost USD 0.0096 in total: about USD 0.005 per image call (3,081 input tokens for a 1024x576 pack photo, 173 output of which 115 hidden reasoning; the sheet: 1,724 in, 638 out). `reasoning_effort` accepts minimal/low/medium/high/xhigh/max (not "none" for this model). On the one pack photo tried, the brand, ingredient, strength and form were right, but the Codigo Nacional was misread (648228.9 against CIMA's 848226); the check digit rejected it, which is the intended safeguard. On the sheet, the first five rows printed matched the truth exactly (the printout was cut at 700 characters); a full scored comparison against Qwen has not been run.
- **Sheet reader with Muse Spark (`muse-spark-1.3`, `sheet_reader_eval.py`, 2026-10-26)**: on the same fictional sheet, 7/7 rows, 28/28 schedule cells and all remarks exact, USD 0.0051, one call. Same caveat as for Qwen: one clean synthetic sheet, so real sheets are untested and every row still needs caregiver confirmation. Doses that do not parse (e.g. "media") are kept as read and block the line instead of being turned into 0.
- **Candidates for packs without a readable code (`candidates_eval.py`, Muse Spark, 12 crops of about 300 px from synthetic scenes, so an indication only)**: the true medicine was the first candidate in 3 of 12 and within the first four in 3 of 12; in 6 the model read nothing and gave no candidates (an acceptable outcome: the caregiver is asked), and in 3 it read a different brand. One wrong read (BETOPTIC for a Casenlax crop) even passed the check digit and exists in CIMA, a valid code for the wrong medicine, probably text of an overlapping pack. This is why the model's reading is only a search query: candidates are shown with the official photo and never enter the plan without the caregiver's confirmation. Through the app with scene_0000 (SAM 3 as a subprocess, about 24 s): 7 boxes without code, 3 proposals, one candidate confirmed and added as `confirmed`.
